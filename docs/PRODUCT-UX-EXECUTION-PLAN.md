# 聚焦型投研产品执行计划

> 创建：2026-07-31
> 状态：P0、P1 已实现；P2 的统一篮子与个股决策上下文已实现；预测/回测证据动线、跨功能共享偏好及 P3/P4 集成仍待实现
> 目标：保留完整投研能力，但按用户真正做决策的顺序呈现，减少信息噪音、重复操作和配置摩擦。
> 关系：本计划取代 `CONVERSATION-UI-PLAN.md` 中 Web 首页与导航的后续产品决策；已完成的对话、上下文与错误处理能力继续复用，TUI 方向不变。

## 1. 产品判断

妈妈炒股不应复制传统行情软件的“功能目录”，也不应把所有能力都塞进对话。更合适的产品结构是：

1. **先看今天**：大盘、关注主题/篮子、自选与持仓异常在一个屏幕内完成扫描。
2. **再逐层下钻**：市场 → 主题/篮子 → 个股 → 预测/回测/资金流等决策工具。
3. **Agent 贯穿全程**：任何数据都可以继续追问，但用户不必先学会怎么向 Agent 提问。
4. **配置只做一次**：本机不要求令牌；远程访问用一次性配对；微信二维码只连接微信消息通道。
5. **完整不等于同时展示**：排行榜、信号、预测、回测继续保留，但出现在合适的上下文，而不是争夺首页注意力。

## 2. 目标信息架构

```text
今日
├── 大盘指数：上证 / 深证 / 创业板 / 沪深 300（紧凑一行）
├── 关注主题与自定义篮子：半导体 / 创新药 / 用户篮子
├── 自选股：涨跌、异动、数据新鲜度
└── 持仓提醒：只展示需要处理的变化

关注
├── 主题/篮子列表
├── 篮子详情：整体表现 + 成分股
└── 个股详情
    ├── 核心行情与持仓上下文
    ├── K 线 / 资金流 / 事件
    └── 预测与回测（决策工具，不是孤立入口）

问 AI
├── 带入当前页面上下文
├── 解释“为什么”与“接下来关注什么”
└── 生成可回看的预测/分析记录

我的
├── AI 配置
├── 微信消息通道
├── 数据与服务状态
└── 后续：交易风格与提醒偏好
```

移动端建议保留 4 个主入口：**今日 / 关注 / 持仓 / 问 AI**；“我的”由页头头像进入。桌面端可以把“我的”保留在侧栏底部。个股、预测、回测、信号都是可深链的二级页面，不占用主导航。

## 3. P0 — 零摩擦启动与配置（当前实验）

### 已实现范围

- 本机 `127.0.0.1` 启动默认不要求 Web 访问令牌，陈旧的 `MOMMY_API_TOKEN` 不再干扰日常调试。
- 首次缺少 LLM 配置时自动进入同端口配置向导；Provider 数据复用后端单一真相源。
- API Key 在服务端验证后写入私有 `.env`，并即时刷新 Agent 依赖，无需重启。
- 远程服务启动时显示一次性 6 位配对码；浏览器换取 30 天 `HttpOnly` 会话 cookie，无需复制粘贴 owner token。
- 微信二维码是独立、可跳过、由用户点击后才启动的消息通道连接步骤；不承担 Web 登录。
- “我的”展示数据、AI、微信状态，并提供“重新配置 AI / 连接或重连微信”的明确入口。

### P0 验收门槛

- 本机首次启动：打开 Web → 配置 AI → 可选微信 → 进入 App，全程同一端口。
- 本机再次启动：已配置时直接进入 App，不重复打断。
- 远程首次访问：普通页面自动转到配对页；配对前不请求受保护的配置 API。
- 微信连接：没有用户点击就不获取二维码；验证码只在用户明确提交时发送一次。
- 安全：远程 setup API 不因 `--allow-unauthenticated-remote` 暴露；密钥、上游二维码 ID 和微信凭据不出现在响应中。
- 质量：Python 离线测试、Ruff、strict mypy、Vitest、Vue typecheck、production build、Playwright 全部通过。

## 4. P1 — “今日”一屏总览

### 目的

让用户打开 App 后在一个屏幕内回答 4 个问题：大盘怎样、关注方向怎样、自选怎样、持仓是否有事。首页不再以排行榜或空白对话作为第一印象。

### 页面结构

1. **紧凑指数条**：4 个核心指数；只显示名称、点位、涨跌幅与数据时间，不显示指数代码。
2. **关注主题/篮子**：最多 4 个用户关注项；显示整体涨跌、领涨/领跌成分与异常提示。
3. **自选股表**：桌面紧凑表格、移动端两列信息卡；默认按用户固定顺序，不按涨幅自动重排。
4. **持仓提醒**：只显示触发规则或明显偏离的持仓；无异常时用一行“暂无需要处理的变化”。
5. **问 AI 输入条**：保持可见，但作为继续解释当前盘面的入口，不占据主体首屏。

### 排行榜处理

涨跌榜、资金榜和板块榜移到“今日”的次级“发现”抽屉或独立二级页。首页可以用一句摘要提示“医药板块领涨”，但不默认展示 3 组 Top 10。

### 数据契约

- 新增聚合接口 `/api/overview`，一次返回指数、关注篮子摘要、自选摘要、持仓提醒和各区块 `as_of`。
- 聚合接口只编排现有 service，不复制行情或业务计算逻辑。
- 每个区块独立标记 `ok / stale / unavailable`；部分失败不拖垮整页，也不把错误伪装成空数据。

### 验收标准

- 390×844 首屏可看到指数、至少 2 个关注篮子和自选摘要，不横向滚动。
- 桌面 1440×900 不滚动即可完成核心扫描。
- 首页首次内容请求不超过 2 个 HTTP 请求（聚合数据 + 必要认证状态）。
- 任意卡片 1 次点击进入对应主题、个股或持仓上下文。

### 2026-08-01 实施结果

- Today 的关注区现在展示服务端排序后的前 4 个统一篮子，包含整体涨跌、领涨/领跌、异常、成分数量和行情时间。
- Today 只读取后台快照与本地行情缓存，不因主题行情联网失败阻塞首页；指数由 6 次串行请求收敛为 1 次最长 2 秒的批量请求。
- 缺失、部分缺失和超过 15 分钟的行情分别标记为 unavailable/stale，不把旧数据伪装成实时数据。
- 桌面和移动端保持两列紧凑摘要，一屏仍可继续看到自选与持仓状态。

## 5. P2 — 主题/篮子 → 个股 → 决策工具

### 主题与篮子

- 统一内置主题与用户自定义篮子的展示模型：名称、成分、权重（可选）、整体表现、关注理由。
- 用户可以固定排序、隐藏、不关注；首页只显示已关注项。
- 主题详情默认讲“整体发生了什么”，再列成分股，不从排行榜开始。

内置主题和自选分组现已通过 canonical basket ID 统一；自选分组直接作为自定义篮子，不复制股票集合。关注、隐藏、固定顺序、关注理由和可选成分权重保存在 `portfolio.db`。旧浏览器 `mommy-followed-themes` 状态在首次打开“关注”时自动迁移并删除。

### 个股详情

- 顶部固定核心区：价格、涨跌、持仓盈亏（如有）、数据时间与异常状态。
- 内容分为 `概览 / 走势 / 资金 / 决策记录`，避免一条无限长页面。
- “问 AI”自动携带股票代码、当前 Tab、持仓和最近数据时间，用户不重复描述上下文。

2026-08-01 已完成工作包 4（commit `30d9bc8`）：新增服务端个股决策上下文，聚合同一股票的多笔持仓成本与篮子归属，不触发行情网络请求；个股核心区根据现价计算并展示持仓盈亏，同时保留报价新鲜度。篮子成分进入个股时携带 canonical basket ID，个股页可返回来源篮子。

“问 AI”不再把价格、持仓和页面信息拼进可见问题。浏览器只发送白名单化的股票代码、当前 Tab、篮子 ID 与报价时间；服务端重新读取持仓和篮子事实，以独立 `<page_context>` 附加到正常系统上下文，并明确要求 Agent 对实时价格和盈亏调用工具核验。对话页显示当前上下文且允许一键退出。

### 预测与回测入口

- 个股“决策记录”中展示该股预测、验证状态与相关回测。
- Agent 回答产生预测时，回答下方给出“查看预测记录”。
- 独立 `/predictions` 和回测页面保留深链，用于汇总与高级分析，但不依赖用户从隐藏路由猜入口。

### 验收标准

- 从首页任一主题到成分股详情最多 2 次点击。
- 从任一个股到该股预测/回测最多 1 次点击。
- 每个预测必须显示生成时间、验证时间、状态、依据覆盖和数据新鲜度。

## 6. P3 — 个性化交易风格

这一阶段必须建立在 P1/P2 的信息层级完成之后，不能用“个性化”掩盖基础入口混乱。

### 配置方式

- 首次不强迫填写；在“我的”提供 3 个可解释预设：稳健、均衡、积极。
- 用户随后可调整持有周期、最大回撤敏感度、关注信号、常用主题和提醒时段。
- 所有选项使用自然语言与示例，不暴露 prompt、阈值代码或模型参数。

### 生效范围

- 只改变首页排序、提醒优先级、Agent 回答侧重点和默认回测参数。
- 不篡改原始行情、不隐藏风险、不自动下单。
- 页面必须能说明“为什么这条信息排在前面”，并允许恢复默认。

### 验收标准

- 预设切换后首页变化可预测、有解释、可撤销。
- 同一原始数据在不同风格下数值完全一致，仅优先级与解释不同。
- 没有填写风格的用户仍获得完整、可用的默认体验。

## 7. P4 — 主动提醒与微信闭环

- 微信消息通道复用用户在 Web 中设定的关注篮子、持仓与提醒偏好。
- 通知只发“发生变化且需要关注”的内容；同类事件合并并去重。
- 消息包含一句结论、关键证据、数据时间和回到 Web 对应上下文的链接。
- 微信断线、凭据过期、网关离线在“我的”中明确显示，不静默假装在线。

## 9. 全程约束

- 不接交易下单，不把模型输出包装成确定性收益承诺。
- 不以“功能多”为完成标准；以到达关键信息的点击次数和首屏完成率为标准。
- 不删除高级能力；降低它的默认视觉权重，并提供稳定深链。
- 不静默展示旧数据；所有决策相关数据都带时间与新鲜度状态。
- 不在浏览器存储 API Key、owner token、微信凭据或原始二维码上游标识。
- 不把微信扫码用于 Web 登录；Web 认证和微信消息通道始终是两条独立流程。
