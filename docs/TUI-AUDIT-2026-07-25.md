## 🔴 致命问题(会让 TUI 崩溃)

### 1. `[/red]` 之类输入 → `MarkupError` 进程崩

`append_user()` 把用户原话直接拼进 Rich markup (`src/mommy_chaogu/tui/views/chat.py:662-668`):

```python
log = self.query_one("#chat-log", VerticalScroll)
log.query_one("#chat-welcome").remove()
log.mount(Static(f"[bold]❯ {text}[/]", classes="user-msg"))
```

任何含 `[...]` 的输入(包括测试时随手敲的 `[/red]`、Markdown 链接片段、
含方括号的股票名)都会被 Rich 当成 markup 解析,抛出 `MarkupError: closing tag
'[/red]' does not match any open tag`,触发布局循环异常,TUI 退出。

同类问题同样存在于:
- `append_hint()` — `chat.py:736-740`
- `tool_indicator.py:127-129` (format_result_digest)
- `cards.py:95-121` (watch / portfolio 卡片字段)
- `WorkflowCard` 行 (`chat.py:828-841`)

### 2. `/clear` 第一次就崩

`clear_messages()` 异步移除旧 widget 后立刻挂载同名 `chat-welcome` 卡片
(`src/mommy_chaogu/tui/views/chat.py:847-862`):

```python
log = self.query_one("#chat-log", VerticalScroll)
log.query("*").remove()                                      # ← 异步
log.mount(Static("", id="chat-welcome", classes="welcome-card"))  # ← 立刻挂
```

旧 widget 还没 detach 就撞 `DuplicateIds`,TUI 终止。`Ctrl+L` 同样走这条路。
清除过程中 `_busy` / `_working` / 回调全部未清理,busy 时清屏会留下
`_busy=True, _working=None` 的诡异状态,后续回调还能 mount 到已清空的对话流里。

### 3. Esc 取消是"假取消",旧 worker 会污染下一轮

`action_cancel_chat()` 立刻 `set_busy(False)` (`chat.py:868-897`),但后台 LLM 流
可能还在跑。下一轮开始时:

- `_cancel_event` / `_stream_usage` / `_turn_started` 在 `app.py:205-237` 被重置
- 旧 worker 完成时调 `_on_agent_done()` 是按"当前 turn"操作(`app.py:422-462`)
- 结果旧 worker 关闭了新轮的 busy、然后把新答案**再贴一遍**

Pilot 复现:按 Esc 中断 → 立刻发新消息 → 出现 **三条 assistant 气泡**:
中断的旧答案 + 流式的新答案 + 重复贴的新答案。

`workflow` 那一支同样有这个问题:worker 取消事件从未传给 `execute_workflow()`
(`app.py:260-285`),`_on_workflow_done()` 只看旧的 `_cancelled` 标志
(`app.py:292-304`),下轮开始 reset 后旧 workflow 还能补一刀。

### 4. 数据库锁/损坏 → 启动即崩

`MommyTuiApp.__init__()` 同步调 `Services.bootstrap()` (`app.py:117-119`),
`CacheStore` / `WatchlistStore` / `PortfolioStore` 的构造
(`services/bootstrap.py:220-233`) 在 Textual 还没挂载时跑。SQLite 5 秒 busy
超时后仍打不开会直接抛 — Textual 还没机会画第一帧,用户只看到栈跟踪。

只缺 db 文件没问题(schema 会自动建);**锁住 / 文件损坏 / 父目录不可写** 才会复现。

## 🟠 高概率 bug(竞态 / 边界 / 错位)

### 5. 多轮对话根本没历史

TUI 调 `AgentBridge.chat(text, ...)` 时**没传 history** (`app.py:343-352`),
bootstrap 构造的 `AgentService` 默认 `MemoryService(..., memory=None)`
(`agent/service.py:211-222`)。用户问"茅台怎么样" → 收到回答 → 再问"它的市盈率呢?"
→ agent 不知道前面聊的什么。

`ChatView._history` 只是输入框命令历史回填,不是 agent 上下文。

### 6. `/portfolio` 在真实数据下全空

`FakeServices` 走扁平 schema,生产 `PortfolioStore.summary()` 把 `code`/`name`
塞在 `position` 子表 (`src/mommy_chaogu/portfolio/store.py:281-290`)。
`portfolio_card()` 却按顶层 `code`/`name` 字段读 (`widgets/cards.py:250-267`)。

真实数据下每一行**代码和名字列都是空的**。测试通过是因为 `FakeServices` 用了
不同的扁平 schema,把生产 bug 完美掩盖。

### 7. 无 API key 时自然语言查询返回空白

`Services.bootstrap()` 即使没有 key 也会构造 `NLRouter`
(`services/bootstrap.py:273-305`),路由在 `has_agent()` 检查之前发生
(`app.py:217-237`)。`WorkflowExecutor` 在没有 summarizer 时 `summary=""`
(`workflow/engine.py:248-259`),TUI 只显示"工作流执行完成。"
(`app.py:300-304`)。

结果:"今天怎么样" 在没有 key 时**已经把指数和板块都拉了,但只给用户一句完成语**。

### 8. 联想选到看不见的项

`HintBar` 只渲染 5 条 (`widgets/hint_bar.py:36-57`),`cycle_selection()` 在
所有匹配上循环 (`views/chat.py:309-322`)。输入 `/` 时有 13 条匹配,`@` 联想可能
有 8 条 —— 选中态可能落在看不见的行上,Tab 会执行那个看不见的命令。

Pilot 复现:输入 `/`,↑ 按 13 次选中 `/quit`,HintBar 只显示前 5 条,
`/quit` 是隐藏的选中项。

### 9. workflow 进度行被覆盖

`ChatView._step_widgets` 在多轮间不重置 (`views/chat.py:173`),
每次 `_do_workflow()` 本地 step 索引从 0 开始 (`app.py:260-273`)。
连续跑两个 1-step workflow,**第二个 workflow 的进度行会覆盖第一个的历史行**。

### 10. 6 位代码识别吃全角数字

`_CODE_RE = re.compile(r"\d{6}")` (`views/chat.py:43`) 在 Python `re` 里
`\d` 是 Unicode,`６００５１９`(全角 6 位)会进入 quote 模式,直接当股票代码发给
adapter。ASCII 后面接字母(如 `600519x`)已被 `fullmatch` 正确拒绝,问题**只
在 Unicode 数字**。

### 11. 行情源挂了 → `/watch` 显示"还没有自选股"

`DataService.watchlist_quotes()` 在批量报价失败时返回 `[]`
(`services/bootstrap.py:47-84`),即使存储的代码列表非空。
`/watch` 于是说"还没有自选股" (`widgets/cards.py:217-229`) —— **事实错误**,
应该告诉用户"行情源暂时不可用"。

### 12. 输入框里的"白色闪烁"(`zi` 闪)

> 用户报告:发完命令后输入框闪过白色背景的字。

**根因(已复现)**:Textual `Input` widget 的 `render_line` 在输入为空 + 有焦点时,
把 placeholder 第一个字符用 `input--cursor` 样式渲染
(`textual/widgets/_input.py:624-634`)。`input--cursor` 在 `:ansi` 模式是
`background: ansi_white; color: ansi_black`(`textual/_input.py:230-234`)。

`cursor_blink` 默认 `True` (`textual/_input.py:251`),`pause=not (cursor_blink
and has_focus)` 每 0.5s 翻转。提交后 `event.input.value = ""`(`chat.py:413`)
→ 输入框空 → placeholder 第一个字"输"被光标染成白底黑字 → 闪烁。

**这是 Textual 默认行为**,但 TUI 默认主题下用户的终端若不支持 24-bit 色,
:ansi 回退让闪烁非常刺眼。打字时光标在文字上不太显眼,提交后落到 placeholder
第一个字就立刻被注意到。

修法两种,见下方「修复建议」#1。

## 🟢 代码质量(不立刻咬人)

- **renderer 异常被吞** —— `renderers.py:37-50` 捕所有异常返回 `None`,
  schema 错误或数字越界会无声消失,没日志。
- **`_suggestion` 是 Textual 私有 reactive** —— `views/chat.py:348-363` 直接写
  `prompt._suggestion`,`textual>=8.2.8` 漂移后此法失效,目前有 `hasattr` 防护,
  downgrade 只丢 ghost 跟随。
- **`bootstrap.py:106-113` 持仓快照异常用 bare `pass`** —— 静默吃,排错极难。
- **测试漏** —— 现有 162 个测试都走 happy path,缺少:
  - 首次 `/clear` (复现崩溃 #2)
  - busy 时清屏
  - Esc 取消后立刻发新消息 (复现 #3)
  - 连续 workflow
  - 含 `[/...]` 的原始输入 (复现 #1)
  - 生产 `PortfolioStore.summary()` 形态 (复现 #6)
  - 无 key 走 workflow (复现 #7)

## ✅ 已验证 clean

- `SLASH_COMMANDS` 13 条全部有对应 dispatch 分支,`/flows` 无参看自选榜已实现。
- worker 线程经 `call_from_thread` 调 UI 操作,没发现主线程直接改 widget。
- 缺 LLM key 不让 `bootstrap()` 崩,数据 slash 命令仍可用(空 summary 是另一回事)。
- 缺 db 文件自动建父目录 + schema。
- 行情 / 自选股 / 指数的网络调用都在 worker 里,有异常边界,网络失败时降级而非崩溃。
- 6 位代码匹配用 `fullmatch`,只是以六位数字开头不会被误路由。
- 中文和句中 `@` 都能正确识别,Tab 替换 / Enter 接受行为正确。
- `?` 在输入框有焦点时**会被插入**,这点和设计意图一致(HelpScreen 弹窗是另一条路径)。
- `ToolIndicator` 计时器在 detached 时停止,长会话不漏 timer。
- `mommy-tui` 在 `pyproject.toml:28-43` 和 `cli.py:234-260` 注册正确。

## 修复建议(按 ROI 排序)

### P0 — 必修

1. **Turn ID + worker handle** (`app.py:205-462`, `views/chat.py:868-897`)
   - 引入单调递增的 turn id,所有回调携带并在 stale 时丢弃
   - `Esc` 触发真取消信号但**保持 UI busy 直到 worker 实际退出**
   - `cancel_event` 传入 `execute_workflow()`
   - 解决 #3

2. **所有动态字符串走 `rich.markup.escape` 或 `markup=False`**
   - 改 `append_user` / `append_hint` / `tool_indicator` / `cards` 全部动态字段
   - 解决 #1

3. **`/clear` 改成 async 原子操作**
   - 先 await 子 widget 移除,再挂欢迎卡
   - 同时取消 in-flight turn / card worker / 行情 watcher
   - 重置 `_busy` / `_working` / `_tool_widgets` / `_step_widgets` 等所有相关状态
   - 立即恢复缓存或主动刷新一次
   - 解决 #2

### P1 — 应该修

4. **ChatInput 设 `cursor_blink=False`**(`views/chat.py:127`)
   - 一行改动,解决 #12
   - 备选:在 `styles.tcss` 覆盖 `input--cursor` 背景色

5. **真实 portfolio 形态 + 修 `portfolio_card`**(`widgets/cards.py:250-267`)
   - 任选一:让 `DataService` 拍平,或让 `portfolio_card` 读 `position.code/name`
   - 加一条用真 `PortfolioStore.summary()` 的测试
   - 解决 #6

6. **无 key workflow 走 `_format_fallback()` 或渲染 step 结果卡**
   - `app.py:300-304` 在 `has_agent()` 假时直接展示卡片而不是只说"完成"
   - 解决 #7

7. **把对话历史传给 agent + pass `memory` 参数**
   - `app.py:343-352` 用有界历史列表调 `chat`
   - bootstrap 时给 `MemoryService` 传 `ConversationMemory`
   - 解决 #5

### P2 — 排期修

8. **联想选中和显示分页**(`widgets/hint_bar.py:36-57`)
   - 选中态要么限制在可见 5 条内,要么虚拟滚动
   - 解决 #8

9. **`_CODE_RE` 收紧**(`views/chat.py:43`)
   - 改为 `re.compile(r"[0-9]{6}")` 排除全角
   - 解决 #10

10. **`/watch` 区分"空表"和"行情源挂"**(`services/bootstrap.py:47-84`)
    - 拉取失败时返回特殊 sentinel,卡片显示"行情暂不可用"
    - 解决 #11

11. **`workflow` 步骤行加 turn_id 前缀**(`app.py:260-285`)
    - `_step_widgets` 用 `(turn_id, step_idx)` 复合 key
    - 解决 #9

### P3 — 早晚修
