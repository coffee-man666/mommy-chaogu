工程 × 能力 — mommy-chaogu

根病一句话：底座深，跨缝浅。单语言内的 derive-don't-duplicate 纪律是真实成立的 （37 工具单一注册表、import 期一致性校验、mypy strict 零豁免、2,301 个离线用例）； 但每一个跨语言（Python↔TS）、跨入口（TUI↔Web↔DSH）、跨文档（代码↔AGENTS/README） 的形状都活在多份手抄里——而且漂移不再是假设，是实测：TUI 标签表注释自称「覆盖全部工具」实际缺 5 个， web 侧缺 12 个；审批语义存在五种编码且漂移方向是 fail-open；代码正则真相源只迁移了 2/23 个使用点， 同一个 MCP server 对 BRK.B 给出两种答案。 这些手抄分别落在三类损伤里：会说谎的、 被拖慢的、长不大的。

底座健康 能用但有条件 / 被拖慢 会说谎或封顶

本次深挖结合两个前序会话：四阶段验收测试（发现 A8/A10/A11 三项宿主高危）与修复会话 （落地 SSE 重连 / MCP 看门狗 / 参数透传 / dock 拖拽，即当前未提交的 494 行）。上次评审（08-15）八候选落地 2.5 个，记分卡见英文记录层。

01 · 能力清单（数字全部在 HEAD 实测）

行情与确定性计算

37 工具 / 12 域，TUI/Web/CLI/MCP/DSH 五入口共用同一 ToolRegistry；quote/bars 有缓存兜底，「拉新失败保旧数据」在 agent 路径成立。

卡点：news/sector/基本面/龙虎榜约 9 个工具走 Protocol 外的半条缝——无缓存无降级（F16）。

DSH 产品嫁接

卡点：跨语言契约全部手抄——审批表五种编码、前缀 6 处字面量、WAL×mtime 失效信号疑点（F1/F2/F8）。

持续监测

7 条内置规则 + 自定义告警 + flows ratio + 业绩比对，规则引擎本身扎实。

封顶：全仓无 scheduler；Server酱只在 web 进程接线（monitor/flows 循环零接线，已 grep 验证）；Bark 完整实现零调用方；无交易时段 gate（F13/F6）。「受支持的自动监测」今天是「受支持的手动监测」。

extract → save → prepare → activate，三次独立确认的语义在代码里齐全（strategies.py + store 强制 note）。

卡点：写面治理三轨不等价——LLM 路径有确认闸，工作流路径无闸且编译器全表喂 37 工具，MCP personal 档靠 LLM 自报布尔（F15）。

五入口一致体验

CLI 17 子命令 + 10 工作流、TUI 16 slash、Web 13 页、MCP 5 宿主、DSH——底座同一套。

卡点：工具表面在 DEFS/TUI/web/DSH 四处镜像，两处已实测漂移；TUI 富卡只覆盖 4/37 工具，8KB 截断让满限结果永远出不了完整卡（F5/F14）。

安装 · 升级 · doctor

产品模式独立 DSH_HOME + profile manifest + 托管 hash，幂等安装经 21 个离线用例。

封顶：Skill 升级路径自锁——previous=None 使未动过的副本在内容升级后必然被判「用户修改」，--force 又会覆盖真修改（F11）；doctor 版本基线靠字符串替换整容（F4）。

质量基建

卡点：dsh-bundle 的 vitest 不在任何 CI workflow 里；嫁接 GUI 层零自动化，只有人工 TEST-PLAYBOOK。

03 · 能力链条（现状 → 卡点 → 解锁）

链 1 · DSH 嫁接的可信度 = 跨语言契约的单一真相源化程度（候选 F1/F2/F8/F12）

嫁接四面真机可用；但 WAL 下 AI 写可能不动主文件 mtime，dock 失效信号是「碰巧可见」而非「必然可见」；数据源抖动时面板显示空自选而非旧价。
错误链三连说谎（exit 0 + 桥 200 + 前端丢 error）+ mtime 只 stat 主文件 + 审批判定五编码、前缀 6 处字面量零交叉断言。
AI 写落盘 → dock 必然刷新；抖动时显示陈旧价 + 来源标注 + 降级提示；审批语义从 MCP annotations 派生，加写工具只改一处。

能力含义：宿主里「允许一次加自选」的联动从概率事件变成产品承诺。

链 2 · 「自动监测」承诺 = 调度与推送的出端（候选 F13/F6/F15）

规则引擎、信号日志、Server酱/Bark 推送实现都在，但一切靠用户手动触发或常驻 web 进程。
全仓无 scheduler；notifier 只在 web/app.py 接线（monitor/flows 循环零接线，已验证）；Bark 零调用方；无交易时段 gate；日报无 push 通道。
一条命令获得「每天 9 点日报到微信」；monitor/flows 循环直推信号；iOS 用户零 Server酱依赖；凌晨不再假告警。

能力含义：产品文档里「受支持的自动监测」从措辞变成行为。

链 3 · 五入口一致体验 = 工具表面从手抄变派生（候选 F3/F5/F7/F14）

37 工具的底层能力五入口同源；但展示面四处镜像已漂移（TUI 缺 5、web 缺 12、注释说谎），文档计数落后实情一代。
标签表/正则/计数各自手抄，无生成无完备性断言；8KB 截断与 120 根上限互不知晓，TUI 富卡 4/37。
新工具上线当天全入口同步可读；BRK.B 全域一致；宿主 Agent 按文档接面不再低估 13 个工具。

能力含义：加一个工具从「N 文件协调编辑 + 靠记忆」变成「改一处 + 门禁兜底」。

链 4 · 安装器的可升级性 = managed-copy 纪律统一（候选 F11/F4）

首次安装幂等、doctor 可跑；但 Skill 内容一升级，未动过的副本必然被判「用户修改」。
previous=None + hash 判定 → 必然 RuntimeError 逼 --force，--force 又覆盖真修改；隔壁 TS presets 的 per-file stamp 才是正确方案；doctor 基线靠 replace 整容。
Skill 无缝升级、真用户修改逐文件跳过；doctor 报真实基线；五件套可以放心迭代内容。

能力含义：产品 Skill 从「冻结态」变成可演进的交付物。

链 5 · Web 组合页性能与服务面宽度 = join 与装配的收编（候选 F9/F10/F16/F17）

持仓页能看，但 20 只持仓 = 20 次逐只上游请求；改默认 adapter 链要动 6 个文件。
持仓×报价 join 四处平行（web 逐只循环）；ToolContext 装配 6 处复制；~9 工具在 Protocol 半条缝上无缓存无降级。
组合页 N→1 次上游请求；adapter 链改动一处生效；限流风暴下全工具面均匀降级而非裸奔。

能力含义：web 体验与 TUI/工具面同源同速，服务面宽度配得上五入口。

结论

这个仓库的核心质量是真实的：单一工具注册表供五个入口、确定性计算的诚实边界经住了真机 GUI 测试、 质量门在热点区真实生效。壳子被拖慢的根源不是缺少工程，而是手抄替代派生—— 每一条跨缝的形状（审批表、工具标签、代码正则、数据目录、版本基线、Skill hash）都是两边各写一份加注释互指。 上次评审 2.5/8 的落地率也说明：评审要被排期，靠的不是指出浅模块，而是说清修好之后用户多了什么。

三波的顺序是刻意 的：会说谎的七处先修（每一处都在污染用户或宿主 Agent 当前能得出的结论）， 被拖慢的五处其次（它们对每次变更收税），天花板的五处是产品形状决策——尤其是「自动监测」那条链， 它决定这款产品是工具箱还是承诺。所有修复的公共纪律只有一条：derive, don't duplicate。
